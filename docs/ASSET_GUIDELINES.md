# Cover and visual-panel guidelines

## Purpose

The project gallery borrows the visual clarity of app-store promotional graphics while staying accurate about each project's real UI. Covers, generated feature panels, and genuine screenshots are different asset types.

## Current asset system

- Every project has a locally hosted SVG cover at the path in projects.json.
- Covers are original vector illustrations generated by scripts/generate_covers.py. They include the project name, category, status, and a category-specific visual motif.
- The catalog also has three store-inspired SVG feature panels per project, generated by scripts/generate_project_panels.py. They summarize the project, key capabilities, and current stack/status.
- Feature panels are original promotional artwork, **not application screenshots**. The footer in each panel labels them accordingly.
- ScholarHub's existing PNG promotional graphics are stored at assets/projects/scholarhub/screenshots/. The source was /home/kali/screenshort/playstore-graphics in the local workspace at implementation time.
- Approved real app captures can be added under assets/projects/<project-id>/screenshots/ and referenced from the project's gallery array. Keep actual captures distinguishable from generated feature artwork in alt text and captions.

## Screenshot workflow

1. Open the actual application at the viewport/device being represented.
2. Capture genuine UI states containing no credentials, personal data, private URLs, test tokens, or real customer information.
3. Choose a sequence that tells a small story: the main screen, one core workflow, meaningful result, and optional settings or detail view.
4. Keep text readable and do not use fake ratings, unsupported claims, or fabricated metrics.
5. For mobile apps, prefer a consistent portrait frame for each product and use actual in-app captures inside the frame. For wide web apps, use landscape captures. Command-line tools should show authentic terminal/report output instead of being forced into a fake phone UI.
6. Add readable alt text describing the visible purpose.
7. Optimize raster images before committing. Prefer WebP/optimized PNG for web screenshots and SVG for simple vector covers/panels.

## App-store-inspired reference

Google Play's official preview-asset documentation recommends using screenshots that demonstrate the actual app experience. Store-upload rules are not automatically requirements for this portfolio website; use them as a visual quality reference only.

Reference: https://support.google.com/googleplay/android-developer/answer/9866151

## Regenerate catalog artwork

~~~bash
python3 scripts/generate_covers.py
python3 scripts/generate_project_panels.py
python3 scripts/generate_catalog.py
python3 scripts/validate.py
~~~

Covers and panels are editable SVGs. The scripts intentionally use no remote font or image assets.
